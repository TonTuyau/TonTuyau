## What was built

**Endpoints** (all `GET`; `HEAD` too for media and art)

| Endpoint | Notes |
|---|---|
| `/api/home` | latest published of each type, sections video → short → stream, empty ones left out |
| `/api/videos`, `/api/channels/{id}/videos` | `type`, `sort` = latest / popular / oldest, `exclude` (a channel's videos since v1.1, `/api/videos` since v1.3), cursor paging |
| `/api/videos/{id}` | `VideoDetail` with `mimeType`, `tracks`, `mediaUrl`, `downloadUrl`, `mediaAvailable`, and the channel's `subscribers` (v1.1) |
| `/api/channels`, `/api/channels/{id}` | name filter as you type, sort name / subscribers, `videoCounts` per type |
| `/api/search` | `kind` = all / videos / channels, filters `type`, `channel`, `published` = today / week / month / year (v1.2), `duration`, sorts relevance / latest / popular |
| `/api/search/suggest` | at most 3 channels first, then video titles fill the rest (v1.1), by word prefix, accents ignored |
| `/media/{id}`, `/media/{id}/download` | original file, one byte range per request, download named after the real title |
| `/art/videos/{id}`, `/art/channels/{id}/{kind}` | from the art store, `Cache-Control` + `ETag`, 304; kinds `thumb` and `banner` (v1.1: any other kind is a 404) |
| `/openapi/v1.json` | generated by the backend; Scalar UI at `/scalar` in Development only |

**Layers** (your rule): controllers bind query/route values and return DTOs (`TonTuyau.Api/Controllers`, `Contracts`); services hold the use cases (`TonTuyau.Application/Browse`: `VideoService`, `ChannelService`, `SearchService`, `CardBuilder`; `Media/MediaService`); validators throw `ValidationException` (`RequestValidators.cs`); repositories run typed Elasticsearch queries (`Repositories.Browse.cs`: `BoolQuery`, `TermQuery`, `DateRangeQuery`, `NumberRangeQuery`, `MultiMatchQuery`, `MatchQuery`, `MatchPhraseQuery`, `TermsAggregation`, `SearchRequest` with `search_after` and `TrackTotalHits`). One middleware (`Errors/ErrorMiddleware.cs`) maps exceptions to ProblemDetails: `ValidationException` → 400, `NotFoundException` → 404, `RangeNotSatisfiableException` → 416 (+ `Content-Range: bytes */<length>`), anything else → 500 with no internals (logged with the request; the answer carries a `traceId`). Bodiless errors (unknown path, `POST`) also answer ProblemDetails (404, 405).

**Paging**
- `search_after` on the list's sort keys, **always ending with the id** (so equal dates or view counts never make pages overlap or skip); relevance pages on `[_score, id]`.
- A page asks Elasticsearch for `size + 1` hits: the extra one says whether there is a next page, so the last page has `nextCursor: null` even when it is full.
- `total` is exact (`track_total_hits: true`).
- Cursor = base64url of `{"f":"<fingerprint>","a":[{"i":…},{"s":…}]}`. The fingerprint is a hash of the list and everything that decides its content and order (filters, sort, search text, channel); the page size isn't part of it. A cursor used with other filters or sort, a hand-edited one, or garbage → 400 on `cursor`. Each value's kind is checked against the sort key it goes to, so nothing a client sends can make Elasticsearch fail.

**Counts**: `videoCounts` come from one `terms` aggregation on `channel_id` with a `terms` sub-aggregation on `type`, for all the channels of the page at once. The front never counts.

**Search**: one `multi_match` of type `cross_fields`, operator `and` (every word must be found, each in any field: "tom huile" finds Tom Cooks' oil video) over `title^3`, `title.en^3`, `channel_name^2`, `channel_name.en^2`, `tags^1.5`, `description`, `description.en` (the M2 French analysis with accent folding + the English sub-fields). The search text as a phrase in the title adds a boost. Channels search `name^3`, `name.en^3`, `tags^1.5`, `description`, `description.en`.

**Suggestions and the channel filter** use the M2 `.autocomplete` sub-fields (edge n-grams when indexing, folded words when searching): every word typed must start a word of the name or title ("tom c" → Tom Cooks). The typed words in the same order rank first. Titles shared by several videos are suggested once.

**`mimeType`** (built in `MediaTypes.PlaybackType`): container from the file extension, then one representative codec string per codec family, video codecs first, each once:

| Extension | Container | | Codec (TA/ffprobe name) | String |
|---|---|---|---|---|
| mp4, m4v, mov | `video/mp4` | | av1 | `av01.0.08M.08` |
| webm, mkv | `video/webm` | | vp9 | `vp09.00.40.08` |
| | | | vp8 | `vp8` |
| | | | h264 (avc1) | `avc1.640028` |
| | | | hevc, h265 | `hvc1.1.6.L120.90` |
| | | | opus | `opus` |
| | | | aac | `mp4a.40.2` |
| | | | mp3 | `mp4a.6B` |
| | | | vorbis | `vorbis` |
| | | | flac | `flac` |

An unknown codec keeps its own name (made safe: letters, digits, `.`, `-`, `_`), so `canPlayType()` answers "no" and the front shows the download button. No tracks → just the container. `mediaAvailable` = not flagged `media_missing` by the full sync.

**Media and art** are always found from the id: id format checked first (`[A-Za-z0-9_-]{11}`, `UC` + 22) → stored document → indexed path → `LibraryPaths` → resolved under the media or art root (with a final "still under the root" check, now also in `MediaLibrary`). A path never comes from the URL. Unknown id, file flagged missing, file absent right now, or no copied image → 404.
- Ranges (RFC 9110): `bytes=a-b`, `bytes=a-`, `bytes=-n` → 206 + `Content-Range`; a range starting past the end (or `-0`, or anything on an empty file) → 416. What a server may ignore (several ranges, malformed header, another unit, `b < a`) gets the whole file (200). `If-Range` with the current ETag or date keeps the range, anything else gets the whole file. Files are sent with `SendFileAsync` (no copy through managed memory).
- `ETag` = size + modification time (strong), `Last-Modified`; `If-None-Match` / `If-Modified-Since` → 304.
- Download: `Content-Disposition: attachment; filename="<ascii>.<ext>"; filename*=UTF-8''<title>.<ext>`. In both names `\ / : * ? " < > |` become `_`, control characters and odd spaces become one space, trailing dots and spaces go, Windows' reserved names (`CON`, `NUL`, `COM1`…) get a `_`, an empty title becomes `video`, and the title is cut at 150 characters (never inside a character or emoji). The ASCII name drops accents (`Crème` → `Creme`, `œ` → `oe`, `’` → `'`) and replaces the rest (`%` too, which old clients decode).
- Art: `Cache-Control: public, max-age=86400` + ETag (see Open questions).

**JSON**: camelCase, enums as lower-case strings (`"video"`, `"short"`, `"audio"`, `"channel"`), dates in UTC `2026-10-02T20:18:48Z`, durations in whole seconds, numbers never as strings, accents written as they are. Card fields come first in `VideoDetail` / `ChannelDetail`, as in the contract.

**OpenAPI**: every operation has its 200 shape and its ProblemDetails (400 with `errors`, 404, 416); `/api/search` answers `oneOf` `SearchAllResponse`, `PageOfVideoCard`, `PageOfChannelCard`; enums are listed (`VideoType` = video / short / stream…). Parameters carry their allowed values in their descriptions. Scalar (`Scalar.AspNetCore` 2.17.13) is mapped in Development only.

Nothing changed in the index definitions: no `index rebuild` needed for M4.

## Decisions taken during the milestone

Choices the contract leaves open; the ones you may want to change are also in *Open questions*.
- **Malformed id → 400, unknown id → 404.** A malformed id is an invalid parameter (and it's how traversal attempts are refused, before any lookup).
- **Dates** (v1, replaced in v1.2 by named periods, see below): `publishedAfter` was "at or after", `publishedBefore` "strictly before".
- **Durations**: short < 240 s, medium 240–1200 s (both included), long > 1200 s.
- **`kind=channels` refuses video-only parameters** (`type`, `channel`, dates, `duration`) and any sort but relevance, rather than silently ignoring them.
- **`kind=all`**: the channels above the videos are searched with the same text, without the video filters.
- **Thumbnail URLs are only given when the image is really in the art store** (a file check per image, local disk), so the front never shows a broken image; `null` otherwise.
- **`/media` Content-Type is what the file is** (`mov` → `video/quicktime`, `mkv` → `video/x-matroska`), while `mimeType` uses the contract's mapping (`video/mp4` / `video/webm`) for `canPlayType()`. Today's library is all `.mp4`.
- **One range per request**; several ranges → the whole file (allowed by RFC 9110; browsers never ask for several).
- **Bodiless errors are ProblemDetails too** (unknown route 404, `POST` 405), with the same `type` URIs.
- **`size=abc`** (a value that doesn't even bind) answers the same 400 shape as the validators: MVC's model-state factory throws a `ValidationException` that the middleware maps.
- **Elasticsearch unreachable → 500** (the contract lists no 503).
- **The OpenAPI document is served in every environment** (the front generates its types from it; it's read-only and LAN-only); the Scalar UI only in Development.
- Browse queries live in `Repositories.Browse.cs` (the repositories are now `partial`), next to the M3 sync queries.

## Deviations from the contract

None. Compatible additions: ProblemDetails carry a `traceId` (to find the request in the log); media answers carry `ETag` / `Last-Modified` and honour `If-Range`; art answers 304 to a matching `If-None-Match`.

## Known limitations / follow-ups

- Relevance boosts are first guesses, checked on the test library and by hand on the real one (see the smoke test); worth tuning once the front shows results.
- Every image URL costs a file check on the art volume (local disk: microseconds). If the art volume ever moves to a network share, cache it.
- `videoCounts` are computed per request (one aggregation per page of channels): cheap at 116 channels, fine at 10×.
- The OpenAPI `oneOf` of `/api/search` references `SearchAllResponse`, whose nested schemas are written inline (ASP.NET Core 10 limitation of transformer-made schemas): the shapes are right, only less factored.
- Media files replaced on the share under the same name change their ETag, so a resumed download or a seeking player restarts cleanly (the RFC behaviour), but a player mid-video may stop.

## Contract v1.1 and v1.2

Branch `feature/m4-contract-v1.1` (off `milestone/m4-api`, with `main` merged in for the contract files). [API_CONTRACT.md](../API_CONTRACT.md) v1.1 and v1.2, from [QA_SESSION_06.md](../QA_SESSION_06.md).

**v1.1**
- **`VideoDetail.channel.subscribers`** (M5a-2). `VideoDetail` is now its own class (it used to derive from `VideoCard`) with a `VideoDetailChannel` (`id`, `name`, `thumbnailUrl`, `subscribers`); `VideoCard.channel` is unchanged (no subscribers). The count comes from the channel lookup the cards already do (0 if the channel isn't in the store).
- **`exclude` on `/api/channels/{id}/videos`** (M5a-3): a video id left out of the items and of `total` (an Elasticsearch `must_not` term on the id). Checked like any id (malformed → 400 on `exclude`), part of the cursor fingerprint (a cursor made with another `exclude`, or none, → 400). An id that isn't in the list changes nothing.
- **`kind=all` later pages: `"channels": []`** (M5a-13). It already was: the service sets an empty list when a cursor is given. Now explicit twice: the mapper also turns a missing list into `[]`, and tests check the field is an array (Reqnroll `"channels" has 0 items`, unit tests on the service and the mapper).
- **Suggestions: at most 3 channels**, video titles fill the rest up to `size` (M4-Q2). `ApiValues.SuggestedChannels`.
- **No TV art** (M5a-17): `tvArtUrl` is gone from `ChannelDetail`, and `/art/channels/{id}/tvart` is a 404 like any unknown kind (also v1.1: unknown kinds used to be 400). The 404 doesn't echo the kind asked for. **The sync is untouched: it still copies TubeArchivist's TV art into the art store**; harmless (a few hundred KB per channel), and never served.

**v1.2**
- **`published` = `today` | `week` | `month` | `year`** replaces `publishedAfter` / `publishedBefore` (M5a-1): published within the last 24 h / 7 / 30 / 365 days. Unknown value → 400; with `kind=channels` → 400 like the other video filters.
- The cut-off (`now − period`) is computed on the **first page** from an injected `TimeProvider` (the one already registered for the sync lock), and **stored in the cursor** (a `t` value, Unix milliseconds), so later pages use the same cut-off even a day or a month later. The period name is part of the fingerprint (a cursor of another period → 400); the cut-off isn't (it travels in the cursor). A cursor of a period search without its cut-off (hand-made) → 400.
- `VideoFilter` keeps only a lower bound (`PublishedFrom`); `RequestRules.TryParseDate` and the date tests are gone.
