# TonTuyau 1.0.0

The first release: a self-hosted, YouTube-like web UI over a [TubeArchivist](https://github.com/tubearchivist/tubearchivist) library, read-only, no login. Design history: [DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md), the Q&A sessions and the milestone notes.

## What's in it

- **Browsing and search** (M5): Home, channels and their tabs, the watch page (player fitted to the video's shape, small / large player, "More from <channel>" scrolling on), a vertical shorts player (or the normal one, a setting), feeds, search with suggestions and filters (the last word typed matches as the start of a word, in every field), FR / EN, light / dark, phone bottom bar, wide-screen grids (up to 6 video / 10 shorts columns, then the cards grow).
- **The sync** (M3): incremental and full, every deletion checked with TubeArchivist, art copied, resized versions made (WebP, `srcset`), automatic index rebuild when the index definitions change. Read-only on TubeArchivist (GET/HEAD only). Command-line syncs print their progress: a line at each step and at most every 10 s (one updating line in a terminal).
- **The API** (M4): read-only REST, cursor-paged, ProblemDetails errors, media with seeking, downloads named after the title, art with caching; [API_CONTRACT.md](../API_CONTRACT.md).
- **Docker** (M7): `ghcr.io/eclegv/tontuyau-backend` and `ghcr.io/eclegv/tontuyau-frontend` (linux/amd64, non-root), a compose stack of three containers; only the front is published. No CPU or memory limits: the stack uses what the VM has, Elasticsearch keeps a fixed heap (`TONTUYAU_ES_HEAP`). The videos are one folder, `TONTUYAU_MEDIA_PATH`, mounted read-only.
- **Security**: a strict Content-Security-Policy (no inline script or style), `nosniff`, `Referrer-Policy: same-origin`, `X-Frame-Options: SAMEORIGIN`; the generic `/health` as the backend's healthcheck (`/health/ready` stays).
- **The logo**: a pipe ("tuyau"), a plumbing elbow with a play triangle flowing out of its mouth, in teal.

## CI and images

- `.github/workflows/ci.yml` runs on **pull requests** to `main` and on **version tags** `vX.Y.Z` only: `scripts/check.sh` (version, compose file, backend format/build/tests, front lint/check/tests/build), then both images. A pull request builds them without pushing; a version tag publishes `X.Y.Z`, `X.Y` and `latest`. A newer push to an open pull request cancels the run in progress.
- GitHub creates a package **private** the first time CI pushes it: make `tontuyau-backend` and `tontuyau-frontend` public once (package settings → Change visibility → Public).

## Capping a container (optional)

The stack sets no limits. To cap one anyway, a `docker-compose.override.yml` next to the compose file, e.g.:

```yaml
services:
  tontuyau-backend:
    deploy:
      resources:
        limits: { cpus: "4", memory: 2g }
```
