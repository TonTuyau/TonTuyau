# TonTuyau 1.2.0

The first part of the administration, on top of [1.1.0](1.1.0.md): **logging in**, and **an admin dashboard** of the library. Kept small on purpose: one admin account, one page.

## What's in it

- **Accounts in PostgreSQL.** A new service, `tontuyau-db` (`postgres:17`, a named volume, a healthcheck, on a network with the backend only, never published), holds the accounts. The first start creates the admin from `TONTUYAU_ADMIN_USER` (default `admin`) and `TONTUYAU_ADMIN_PASSWORD`; later starts don't read them again.
- **Passwords as OWASP recommends**: Argon2id, 19 MiB, 2 passes, 1 lane, a random salt each, stored as PHC strings (the parameters travel with the hash), compared in constant time.
- **Logging in.** `/login` (EN / FR, short words), "Log in" in the top bar, then your initial with a menu: your name, Administration, Log out. ASP.NET Core's cookie: HttpOnly, SameSite=Strict, Secure (`TONTUYAU_COOKIE_SECURE=false` for plain `http://` on the LAN), 8 hours renewed while used, or 30 days with "Stay logged in"; a restart keeps everyone logged in (the cookies' keys are in PostgreSQL). One message for every refusal, "Wrong username or password.", whatever the reason. Browsing still needs no login.
- **5 login attempts a minute per visitor**, then 429. Behind a reverse proxy (cloudflared, nginx…), name it in `TONTUYAU_TRUSTED_PROXIES` (its address as the front server sees it) so each visitor gets their own attempts; only that proxy's `X-Forwarded-For` entry is believed, an address a visitor writes itself never counts.
- **The admin dashboard, `/admin`** (logged-in accounts only; anyone else goes to the login page and back). A YouTube Studio–style left menu, collapsible with ☰. On the page:
  - the library's totals: channels, videos, shorts, streams, **gone from YouTube** (TubeArchivist's `active` flag);
  - the **play time**, in all and per type, with each type's share and average length;
  - the **import history** of a period (last day, week, month, year, all): a bar per sync run, day, week or month in the sync's time zone, split by type; runs from before 1.2 recorded only their total and show as a grey "types not recorded" bar;
  - **every channel** in a table: videos, shorts, streams, gone from YouTube, total; sortable, searchable, a "Gone from YouTube" filter.
- **API**: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `GET /api/admin/dashboard`, `GET /api/admin/dashboard/imports?period=` (contract v1.6, OpenAPI). The admin routes answer 401 to anyone not logged in.
- **The sync records its new videos by type** for each run (for the import history).

Decided along the way (your answers): usernames are case-sensitive; no minimum length for the admin's password; logging out deletes the cookie in the browser (a copy taken before stays valid until it expires: serious account management would come with an identity provider such as Authentik). In the code: Controller → Service → Repository for the database (the rules in the services, the database calls only in the repositories), and null checks that don't rename a value that already has a name.

## Upgrading from 1.1

1. **Back up the new database from now on**: the accounts can't be rebuilt from TubeArchivist (README, Backups: `pg_dump`).
2. In `.env`, add `TONTUYAU_DB_PASSWORD` (any long random string, e.g. `openssl rand -base64 24`) and `TONTUYAU_ADMIN_PASSWORD`. Behind cloudflared or another reverse proxy, add `TONTUYAU_TRUSTED_PROXIES=<its address>`. Over plain `http://`, add `TONTUYAU_COOKIE_SECURE=false`.
3. Take the new `docker-compose.yml` (it adds `tontuyau-db`), then `docker compose pull && docker compose up -d`. The database starts first; the backend creates its tables and the admin account.
4. Log in at `/login`, then "Administration" in the menu under your initial.

The library index, the images and the videos are unchanged: no rebuild.
