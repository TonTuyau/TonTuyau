# TonTuyau 1.3.0

- **Link previews.** A TonTuyau link shared in Discord, Messenger, WhatsApp… shows a card, like a YouTube link does:
  - a video (or a short, or a stream): TonTuyau, the channel, the title and the video, with a player in Discord (the other apps show the thumbnail);
  - a channel: TonTuyau, its name, its description and its icon;
  - any other page: TonTuyau.

  The chat apps' servers don't run the app: they read tags in the page (Open Graph, a Twitter card, an oEmbed document for the channel's name), which the front server now writes into each page from the backend's API. The cards have TonTuyau's teal.

## Known limits

- **Discord's player only plays some files.** Discord passes the video through its own proxy, which handles small, common files (H.264 MP4) but not most of a TonTuyau library (VP9 or AV1, often hundreds of megabytes or more): a big video gets no card at all, a smaller one gets a card whose player doesn't start. Tried on 1.3.0-alpha.1; a card without a player (`work/1.3.0-video-card`) is set aside for now.
- Discord keeps the card it made for a link: a changed card shows on a link it hasn't seen yet.

## Upgrading

Set **`TONTUYAU_PUBLIC_URL`** in `.env` to the address TonTuyau is reached at from the internet, e.g. `https://tontuyau.example.net` (no path), then pull the new images (`docker compose pull && docker compose up -d`; the compose file has the new setting: take the new one too). Without it, nothing changes: no previews.

The chat apps' servers fetch the page, the thumbnail and (Discord) the video at that address: it must be reachable from the internet without a login, like the rest of TonTuyau today. Behind a login (Cloudflare Access, for instance), the previews show nothing.
