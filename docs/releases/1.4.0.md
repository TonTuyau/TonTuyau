# TonTuyau 1.4.0

In progress on `release/1.4.0`, one pull request at a time.

- **A canceled run is Canceled, not Failed.** A run stopped because its caller asked (Ctrl-C on the command line today, the Tasks page later) is recorded as canceled, without an error; what it did until then stays. Losing the sync lock to another process is still a failure.
- **Applying deletions is a run of its own.** `tontuyau sync apply-deletions <run>` used to add its counts and a note to the full run's record, and recorded nothing if it failed. It's now a run in the history (`apply-deletions`), with its start, end, outcome and counts, for the full run whose list it applies; that full run's record stays as the run left it. The dashboard's last sync and import history only count the syncs (incremental and full runs).
- **Every run has a log.** Each run's lines (its start, a progress line at each phase and every 10 seconds, warnings, errors, its end) go to the backend's log as before, the scheduled runs' progress too (they used to log only their start and end), and to the new table `run_log_lines` in PostgreSQL, kept forever. TonTuyau's own lines from Information up, the warnings and errors of the libraries it uses, nothing logged outside a run. The lines are written a batch a second, so a run never waits for the database; if it's down, they wait in memory and are tried again.
- **The backend's runs, one at a time and cancellable.** The backend starts its runs in the background (the scheduled ones now; the Tasks page's and the command line's in the next steps) and knows the one going on, which can be canceled by its id: its log then says who asked. When the backend stops (`docker compose down`, an upgrade), the run going on is canceled, recorded as such, and its log written to the end, instead of being cut off as a failure. The automatic index rebuild after an upgrade stays apart.
- **The Tasks page's API (read).** `GET /api/admin/tasks` (the three tasks: their schedule, next run, last run, the deletion list waiting to be applied, the run going on), `GET /api/admin/runs` (the run history, latest first, a page at a time, or one task's), `GET /api/admin/runs/{id}` and `GET /api/admin/runs/{id}/log` (its lines after a given one, and whether more will come): contract v1.7, logged-in accounts only.
- **Starting a task, canceling a run (API).** `POST /api/admin/tasks/{task}/runs` starts the incremental sync, the full sync, or applying the deletion list that waits, in the backend's background, recorded as started by the logged-in account; `POST /api/admin/runs/{id}/cancel` stops the run going on, and its log says who asked. One run at a time: a 409 while another goes on.

## Upgrading

Pull the new images (`docker compose pull && docker compose up -d`): no configuration change. The backend adds its new table to PostgreSQL by itself at startup.
