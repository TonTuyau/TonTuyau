# TonTuyau 1.5.0

In progress on `release/1.5.0`, one pull request at a time; tried on the VM as `1.5.0-alpha.N`.

The first step of replacing TubeArchivist: TonTuyau reads YouTube itself (metadata only: nothing is downloaded in 1.5).

- **API keys.** Programs use an API key instead of logging in: they send `Authorization: Bearer tt_…`. A key has a **kind**, chosen when it's made, and opens only the endpoints of its kind; it never does what a logged-in admin does (tasks, dashboard, keys). 1.5 has one kind, **browser extension**, for TonTuyau's own extension (its connection test today, the YouTube cookie next). As many keys as you want, each with its own name (unique, whatever the case), shared by every admin. The secret is shown once, when the key is made: TonTuyau keeps only its hash (SHA-256), its first characters to tell keys apart, who made it and when, and its last use. A key can be disabled, enabled again, or deleted, by a logged-in admin. API: `/api/admin/api-keys`, `/api/extension/connection` (contract v1.8).
- **The API keys page.** A new page in the admin area (`/admin/api-keys`, in its menu): making a key (its name and kind; its secret shown once, with Copy), and the keys made, latest first: their kind, the secret's first characters, enabled or not, when and by whom made, their last use; disabling, enabling again, deleting (asked first).

- **yt-dlp in the backend.** The backend image now has [yt-dlp](https://github.com/yt-dlp/yt-dlp) 2026.08.19 and [Deno](https://deno.com) 2.9.7 (which yt-dlp runs YouTube's JavaScript with), pinned and checked against the checksums their releases publish: TonTuyau reads YouTube with them, through [Ytdlp.NET](https://github.com/manusoft/Ytdlp.NET). Nothing reads YouTube yet in this step: the backend's log says, at startup, which versions it found (or warns when one can't be run). A video can be read with its comments too (up to a number given, answers included, YouTube's top comments first, with their author, date, likes, and whether pinned, hearted or by the channel itself), and its comment count. A video or a channel YouTube says is removed, private or terminated is "gone"; anything else that goes wrong (a bot check, too many requests, a country block, the network) is a check that failed, to try again, never "gone". The image is about 160 MB bigger.

- **The YouTube cookie.** TonTuyau's browser extension sends the YouTube cookie of a browser where you're signed in (`PUT /api/extension/youtube-cookie`, with a browser extension key): TonTuyau keeps only its `youtube.com` cookies, in PostgreSQL, checks it at once by reading the account's Liked videos (as TubeArchivist does), and reads YouTube signed in with it from then on (yt-dlp gets it as a file of its own, readable by the backend only, deleted after each run). Its state: works, refused (signed out, expired), or unchecked (the check couldn't tell: a bot check, the network). Its content is never shown nor logged. An admin can check it again or remove it (`/api/admin/youtube`).

- **The Reservoir.** The Elasticsearch service and container are now called `tontuyau-reservoir` (they were `tontuyau-es`): where all the tuyaux lead. Its data volume keeps its name: nothing is re-indexed.

## Upgrading

The Elasticsearch service has a new name, so this upgrade is done in this order:

1. Take the new `docker-compose.yml`. If you have a `docker-compose.override.yml` that names `tontuyau-es`, rename that key to `tontuyau-reservoir` there too (else Compose sees a service without an image).
2. Stop the stack, the old `tontuyau-es` container included (two Elasticsearch on the same data would refuse to start): `docker compose down --remove-orphans`
3. Pull and start: `docker compose pull && docker compose up -d`

No other configuration change. The backend adds its new tables (`api_keys`, `youtube_cookie`) to PostgreSQL by itself at startup.
