# TonTuyau 1.5.1

In progress on `release/1.5.1`.

Smaller, sturdier images; nothing changes in the app.

## Smaller images

- **The backend's image is Ubuntu "chiseled"** (`aspnet:10.0-noble-chiseled-extra`): only what .NET needs (the C and
  C++ libraries, OpenSSL, ICU, time zones), no shell, no package manager, no `tar` nor `login`, run as a non-root user.
  yt-dlp and Deno run in it as before (yt-dlp's zlib is copied in, alone). Known vulnerabilities in the image (Trivy):
  26 → 3, none high or critical, all in libraries .NET needs; and what isn't in the image can't be used by whoever
  would one day get into it.
- **The front's image is Ubuntu "chiseled" too** (`runtime-deps:10.0-noble-chiseled`, which holds nothing of .NET:
  glibc, libstdc++, OpenSSL and certificates), with Node alone copied in from the official image (it carries its own
  OpenSSL): no shell, no npm, no package manager, non-root. Known vulnerabilities (Trivy): dozens in the system and 12
  in npm (4 high) → 2 (medium, in glibc). Google's "distroless" Node was tried: its Node lags behind Node's security
  releases, and its Debian base showed 49.
- **`tontuyau health`**: asks the backend running in the container whether it answers (exit code 0 or 1). It's the
  backend container's health check now (it used bash, which the image no longer has).
- **CI runs what each image carries before publishing it**: yt-dlp, Deno and `tontuyau --version` in the backend's,
  Node and the front server's file in the front's. A program missing a library shows at once.

## Upgrading

Take the new `docker-compose.yml`: the health checks changed (the old ones need bash, or `node` on the PATH, which the
images no longer have: the containers would never turn healthy, and the front wouldn't start). Then
`docker compose pull && docker compose up -d`. `docker exec tontuyau-backend sh` (or `bash`) no longer works; the
command line, the logs and `docker cp` do.
