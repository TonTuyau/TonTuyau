# TonTuyau 2.3.0

**Accounts for everyone who watches**: admins and users, made by hand or from an LDAP directory, and a library that
only its accounts can see. And a big task no longer makes the others wait: **Run now**.

## Accounts and roles

- **Two roles**: an **admin** does everything, as before; a **user** watches the library, without the administration
  (its menu has no Administration, the admin pages say they're for admins, the admin API answers 403).
- **The admin's Accounts page**: make a local account (a name, its password typed twice, a role); change an account's
  role or password, disable it, delete it. The last enabled local admin stays (with the directory down or
  misconfigured, it still logs in), and nobody disables nor deletes their own account.
- **My account** (the account menu): the name, the role, where the account is from, and its password changed, the
  current one first. Its other sessions end; this one stays.
- **Sessions checked every 5 minutes**: an account disabled, deleted, or whose role or password changed is logged out
  then.

## A library for its accounts only

- **"Who can watch"** on the Accounts page: everyone who reaches TonTuyau (the default, as before), or the logged-in
  accounts only, at once.
- Then anyone else sees the login page in place of any page, and lands on the page asked for once logged in. The
  library's API, thumbnails, videos and streams answer only to a session; LaPompe's API key and `/health` keep
  working.

## Logging in with an LDAP directory

- **The admin's LDAP page**, set as Jellyfin's LDAP plugin is (its values copy over): the server (StartTLS, a CA
  certificate for a directory with its own), a service account (its password never shown back), the base DN, the UID
  and username attributes, a **users filter** and an **admins filter** (e.g.
  `(memberof=cn=tontuyau,ou=groups,dc=example,dc=com)`), the password attribute and a password reset URL.
- **Four tests, each on its own**: the connection, who the admins filter finds, who the users filter finds, a name
  looked up; none asks for a password. The page also lists the local names the directory has too.
- **A name that isn't a local account's logs in from the directory**: an admin if the admins filter finds it, a user
  if the users filter does. Its role is read again at each login and every 5 minutes: taken out of the group, it's
  logged out. A name both local and the directory's is the local account's only.
- **A directory account changes its password on My account**: the service account changes it in the directory (on
  LLDAP, put it in `lldap_password_manager`), or the account itself where the directory refuses that (an LLDAP
  admin's).
- **"Forgot your password?"** on the login page leads to the directory's page, once a name is typed.
- Tested against LLDAP 0.5.0. OpenLDAP should work too (untested; its `memberof` filters need the memberOf overlay).

## Run now: a big task no longer holds the others

- **"Run now" on a waiting task** (the Tasks page's queue, and the run's page): it goes first. A refresh or a YouTube
  sync going on (say, a channel's 2,000 videos being added) is put on hold for it, and goes on right after it, where it
  stopped. An import going on isn't held: the task starts once it ends.
- **A task put on hold by hand lets the queue go on**: the other tasks run meanwhile. Its **Resume now** while another
  task runs puts it first in the queue: it goes on once that one ends (it was refused before).
- **A sync on hold for disk space lets the queue go on** too (the refreshes download nothing).
- **On hold because YouTube refused**, the queue still waits (YouTube would refuse the next tasks too), and the Tasks
  page now says which task it waits for, and why. Run now still starts a task then.

## Fixes

- **A failed "Download a video" is listed in its channel's failed downloads**, as a sync's are, so it can be tried
  again from there (it was the run's failure alone).
- **A run canceled while it waited on Elasticsearch ended "failed"**: it ends canceled now.

## Upgrading

- **Everyone logs in again once**: the sessions from before 2.3.0 end at their first check. The accounts there are
  local admins, as they were.
- The library stays open to everyone, and the directory off, until the admin sets them.

## For developers

- API (contract v2.13): `GET /api/auth/me` gains `displayName`, `role`, `source`; `PUT /api/auth/me/password`;
  `GET /api/auth/access`; `/api/admin/accounts`; `/api/admin/settings/access`; `/api/admin/settings/ldap` and its
  `test`. `[Authorize]` alone is an admin's session now.
- API (contract v2.14): `POST /api/admin/runs/{id}/run-now`; a run gains `heldFor` and `firstAt`; `GET
  /api/admin/tasks` gains `queueWaitsFor`; resume while another run goes on queues the run instead of a 409.
- The mock's `/__mock?queue=youTube|hand|none` seeds a busy Tasks page.
- The integration tests run an LLDAP container (its directory reset before each scenario).
